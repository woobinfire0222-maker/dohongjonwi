[Supabase 웹 푸시 설정]

1. Supabase SQL Editor에서 push_notifications.sql 전체 실행

2. Supabase Dashboard > Edge Functions에서 send-push 함수를 생성/배포
   이 ZIP의 supabase/functions/send-push/index.ts 내용을 사용하세요.

3. Edge Function Secrets에 아래 5개를 등록하세요.
   SUPABASE_URL = 현재 프로젝트 URL
   SUPABASE_SERVICE_ROLE_KEY = Supabase Project Settings > API의 service_role 키
   VAPID_PUBLIC_KEY = 아래 공개키
   VAPID_PRIVATE_KEY = 별도로 받은 개인키
   VAPID_SUBJECT = mailto:관리자이메일@example.com

   중요: service_role 키와 VAPID_PRIVATE_KEY는 절대 GitHub Pages 코드에 넣지 마세요.

4. Database Webhook 생성
   Supabase Dashboard > Database > Webhooks(또는 Integrations > Webhooks)
   Table: public.notifications
   Events: INSERT
   Target: Edge Function
   Function: send-push
   POST body는 기본 webhook payload(record 포함)를 그대로 사용하세요.

5. GitHub Pages에 아래 파일이 루트에 있어야 합니다.
   index.html
   push-notifications.js
   service-worker.js

6. 처음 사이트에 들어오면 '알림을 켜시겠어요?'가 표시됩니다.
   '알림 허용'을 누르면 브라우저 권한 요청 → push_subscriptions 저장 순서로 진행됩니다.

[주의]
- 브라우저가 지원하는 환경에서 사이트를 닫아도 푸시를 받을 수 있습니다.
- 사용자가 브라우저 알림을 차단하면 사이트가 강제로 다시 허용시킬 수 없습니다.
- GitHub Pages의 HTTPS가 필요합니다. 현재 커스텀 도메인 HTTPS를 사용하면 됩니다.
- 기존 관리자 '전체 알림 보내기' 기능이 public.notifications에 INSERT하는 구조라면 별도 코드 변경 없이 webhook이 이를 받아 푸시합니다.
